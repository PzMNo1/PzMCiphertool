# Taste Principles

Use this file when fusion needs a distinctive judgment layer rather than a mechanical aggregate.

## Taste Is Operational

Taste must change decisions. Convert taste into:

- what to omit
- what to sequence first
- what to make denser or quieter
- what to expose as a user choice
- what to validate before completion
- what to reject even if technically compatible

Avoid vague labels such as "excellent", "premium", or "elegant" unless they are tied to observable choices.

## Fusion Taste Defaults

Prefer:

- coherence over coverage
- sharp triggers over universal claiming
- progressive disclosure over context hoarding
- explicit precedence over hidden compromise
- durable workflows over clever one-off prompts
- direct evidence over plausible confidence
- local patterns over imported abstraction
- high-signal writing over ceremonial documentation

## Distinctiveness Rules

A fused skill should become distinctive through judgment, not ornament.

Ask:

- What can this skill now decide that the source skills could not decide alone?
- Which conflict does it resolve better than a generic merge?
- What repeated failure does it prevent?
- What does it deliberately refuse to do?
- What proof would show that the fused skill improves results?

## Quality Gates

Before finalizing a fused skill, check:

- Does the trigger description identify real use cases and avoid stealing unrelated work?
- Does SKILL.md contain only always-needed instructions?
- Does every reference have a clear reason to exist?
- Does every script solve a repeatable mechanical problem?
- Are contradictions resolved with named precedence rules?
- Can another agent apply the skill without reading hidden build notes?
- Would the fused skill produce a more coherent artifact than simply loading all source skills?

## Anti-Patterns

Avoid:

- anthology skills that concatenate everything
- over-broad "universal" language with no selection rules
- taste expressed as branding instead of decision pressure
- conflict avoidance through generic compromise
- references that duplicate SKILL.md
- scripts that write outside the explicit target scope
- validation claims based only on intent
